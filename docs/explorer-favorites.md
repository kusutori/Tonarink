# 资源管理器收藏设备菜单

Windows 11 的 MSIX 版可在“设置 → 文件资源管理器右键菜单”中开启“在子菜单中显示收藏设备”。该子开关默认关闭，并跟随主开关的可用状态。

- 子开关关闭：保持原有单项菜单，点击“使用 Tonarink 发送”将所选项目加入发送列表
- 子开关开启且有收藏设备：该项变成子菜单，包含“添加到发送列表”及当前收藏设备；点击收藏设备直接向该设备发送本次选中的文件或文件夹
- 没有收藏设备：回退为普通单项菜单，点击“使用 Tonarink 发送”将所选项目加入发送列表，不显示仅有一个入口的子菜单

菜单从应用的收藏存储读取设备名称和指纹，不另建一份收藏配置。每次枚举读取本地快照，不在 Explorer 的 COM 回调中进行网络发现或探测。收藏修改在下次打开菜单时读取；设备名称中的 `&` 按普通字符显示。

## 激活与发送

Shell 扩展先将路径及可选设备指纹写入临时 JSON 文件，关闭文件后原子重命名到应用的共享请求目录，再通知或启动应用。应用继续兼容原来的 `.txt` 请求文件。所有网络操作都在应用中执行。

收藏设备菜单与 Windows 分享建议联系人共用 `ShareTargetPayload.SuggestedContactFingerprint`、文件导入、收藏解析及传输流程；发送页收藏列表的发送入口也复用同一套解析和排队机制：

1. 导入选中内容，保留在发送列表中；自动发送只使用此次导入的项目，不带上列表原有内容
2. 等待服务及 UI 运行时就绪，最长 30 秒；已经暂停或启动失败时提示手动启动，不静默改变用户的暂停设置
3. 最长 20 秒、最多 4 轮解析目标，刷新发现并尝试当前发现的地址及收藏的旧地址；重试间隔为 0.8、1.6、2.4 秒，单协议探测最多 1.5 秒
4. 核对目标指纹后开始一次传输；离线、收藏被删除或服务不可用时保留内容并提示，可手动重试或选择其他设备

连续的直接发送请求在应用中排队，并等待当前传输或 PIN 提示结束。需要 PIN 时沿用现有输入流程；传输失败、拒绝或超时后不自动重发，避免重复发送。页面卸载时取消尚未完成的自动解析，已导入内容保留在发送列表中。

这与 SendTo 目录中的快捷方式是两套独立集成，不创建 SendTo 子目录，也不增加包权限。相关 Shell 接口采用源生成 COM 适配，维持 Native AOT 构建方式。
